# amis-helper v1.2 批次 4 评审意见

## 总评

方案方向正确（SSOT 化正向自检清单、~60 行体量、终检脚本自动验收），但有 **2 处硬错误必须先改**：

1. 文件位置偏离迭代计划原文，且「批次 4 任务原文指定 examples/」无据；
2. 32 条覆盖遗漏 **D-10**（实际只覆盖 31 条）。

另决策点 3 尺度、决策点 4 措辞、终检脚本 2 有缺口需补齐。

---

## 决策点逐项

### 决策点 1 文件位置 —— ❌ 修改

**结论**：应放 `references/self-check.md`，不放 `examples/`。

**证据**：迭代计划原文**四处一致写 `references/self-check.md`**，零处写 `examples/`：

| 位置 | 原文 |
|---|---|
| §4.1 目录树（L282） | `references/ └── self-check.md` |
| §5.2 任务 1.2.5（L420） | `新增 references/self-check.md` |
| §6.2 标题（L488） | `### 6.2 自检清单设计（references/self-check.md）` |
| §6.4 触发矩阵（L522） | `任何生成任务完成后 → references/self-check.md` |

故评审输入里「理由：批次 4 任务原文指定 examples/」**不成立**，与基准文档矛盾。

**语义**：self-check 是「检查项 + 规则 ID 引用」的 .md 清单，不是可复制 JSON 片段，与 `pitfalls.md`（事后排障）对称，同属规则体系而非示例。放 `examples/` 会制造游离文件——`examples/` 现有 7 个文件而 `INDEX.md`/`SKILL.md §4` 只索引 6 个 .json。

**改法**：
1. 位置 → `references/self-check.md`
2. `SKILL.md` 触发矩阵 §3 补一行：

```markdown
| 任何生成任务完成后 | references/self-check.md | 强制自检 |
```

### 决策点 2 分组切面 —— ❌ 修改（遗漏 D-10）

**结论**：32 条实际只覆盖 **31 条**，遗漏 **D-10**（弹层内嵌选择器：`dialog/drawer + crud(loadDataOnce) + bulkActions + ${selectedItems|pick} + disabledOn`）。

现分组 D 域只出现 10 条（D-01~D-09 + D-11），缺 D-10：

| 分组 | 覆盖 ID | 核对 |
|---|---|---|
| 通用必查 | R-01, A-02 | ✅ 2 条 |
| CRUD 列表页 | C-01~C-08 | ✅ 8 条 |
| 弹层提交 | D-01, D-04, D-05, D-06, D-07, D-03 | ⚠️ 6 条 |
| 下载导出 | D-02, D-08, D-09 | ✅ 3 条 |
| 表单控件 | F-01~F-10 | ✅ 10 条 |
| 接口刷新联动 | A-01, D-11, C-02 | ✅ 3 条 |
| **缺失** | **D-10** | ❌ |

**改法**：D-10 归入「弹层提交」组，组名建议改「**弹层与动作**」（因 D-07 确认弹层、D-03 reload 定位、D-10 内嵌选择器都非严格「提交」，现组名已名不副实）。

**优化建议（非硬错）**：A-01 归「接口刷新联动」组名不贴切——A-01 本质是「Service 数据域作用域」（loading 变量机制），与「刷新」无关，且与下载组的 D-08/D-09 强关联。建议移到「通用必查」（与 A-02 并列），让「接口刷新联动」组只剩 D-11 + C-02（纯刷新定位），组名与内容更贴合。

### 决策点 3 条目形态与行数 —— ⚠️ 修改（尺度需明确）

**结论**：方向对，但「不复述写法」若执行到「不提属性名」，问句会空洞、无法独立判断。

**改法**：以迭代计划 §6.2 原文示例为粒度基准——正向问句**必须含判断所需关键词**（属性名/组件名），只「不贴完整 JSON 片段、不复述规则正文」：

```markdown
- [ ] perPageAvailable 放 crud 顶层？→ C-01
- [ ] 事件动作内 reload 用 componentId 而非 target？→ D-03
```

同时允许 **≤1 行极简括注**保留易混点区分，否则 D-03（target 仅 action 按钮合法）、D-11（未实测，与 D-05 边界相反）无法独立判断。

**行数**：~60 行达标（32 条 + 6 组标题 + 头部），上限 120 行宽裕，无问题。

**⚠️ 额外提醒**：§6.2 原文示例的 ID 有错位，落地时**须以 references/ 真实 ID 为准，勿照搬**：

| 原文 | 错误 | 正确 |
|---|---|---|
| L503「统计条 tpl → C-02」 | C-02 实为 id+name 双设 | **C-04** |
| L504「crud 双设 id+name → C-03」 | C-03 实为 syncLocation | **C-02** |

### 决策点 4 META 第 56 行 —— ❌ 修改（随决策点 1 连带）

**结论**：现改法基于错误的 `examples/` 位置，「不属示例」括注恰暴露语义冲突。

**改法**（位置改 references/ 后）：

```
- 参考文档：5 份 + 1 份自检清单（references/self-check.md，批次 4 新增）；示例：6 个 .json + 1 个 examples/INDEX.md 索引（批次 3：原 crud-full.json 拆 4 片段 + 2 保留）
```

注：self-check 是引用清单，**不计入 32 条权威规则数**（META L54 无需改）。

## 终检脚本设计核查

### 脚本 1（权威形态唯一性）—— ✅ 可行，补 3 点边界

逻辑成立，但需明确：

1. **校验范围** = `amis-helper/` 下全部 `.md`（META/SKILL/references×5/examples/INDEX/self-check）；`.json` 不含规则 ID，不参与。
2. **两类权威形态正则**：R 域 `^### \`R-\d{2}\``；其余域 `\*\*\`[CDFA]-\d{2}\`\*\*`。
3. 确认只统计「带权威包裹」的形态——META L46 组合引用（`D-01/D-04/D-05/D-08`）、L54 计数行（`R×1+C×8...`）均为裸引用不带 `**`，天然不误判，脚本口径需明确排除。

### 脚本 2（连续性与悬空引用）—— ⚠️ 缺 2 项关键校验

「编号连续性」部分已核对现状一致（C1-8/D1-11/F1-10/A1-2/P1-16/R×1），✅。

「悬空引用」部分**缺两项，否则达不到「无悬空引用」验收目标**：

1. **self-check.md 的 ID 白名单校验**：约束明确「只引用已冻结 32 条 + P-01~P-16 且不引用不存在文件」，但脚本 2 未覆盖「self-check 内引用的 ID ∈ {32 权威 + P-01~P-16}」这一最关键的悬空来源（如误引 C-02/C-03 错位，或引了不存在的 D-12）。
2. **SKILL.md 索引表 + 各 references 交叉引用的 `references/<file>.md §N` 指向校验**：现只写「references/*.md §N 章节存在」，需明确覆盖 SKILL.md §1 硬规则表、§3 触发矩阵，以及 crud/dialog-actions/form-controls/data-source 内的全路径 `§N` 引用是否真实存在。

**建议补一条**（脚本 2 增项）：

```
脚本3_selfcheck引用白名单: 提取 self-check.md 内所有 `X-xx` 引用，断言 ⊆ 冻结集合{32权威 + P-01~P-16}，且无重复权威定义形态
```
